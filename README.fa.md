# CF-SCAN — اسکنر آی‌پی تمیز کلودفلر برای VLESS + WebSocket

[English](README.md) · **فارسی**

این ابزار آی‌پی‌های کلودفلری را پیدا می‌کند که **واقعاً با کانفیگ VLESS + WebSocket خودتان** کار می‌کنند و
**سرعت واقعی دانلود و آپلود را از داخل تونل** اندازه می‌گیرد؛ دقیقاً همان مسیری که V2rayN / Xray استفاده می‌کند.

* یک فایل (`cf_ping.py`) و **بدون هیچ وابستگی** — فقط Python 3.8 به بالا
* روی **ویندوز** و **لینوکس** کار می‌کند (روی مک هم باید کار کند)
* قابلیت ادامه‌ی اسکن، داشبورد زنده، و لینک‌های `vless://` آماده‌ی ایمپورت در خروجی

---

## چرا نسخه‌ی ۴ ساخته شد؟ (باگ «اینجا ۱۰ مگابیت، در V2rayN صفر!»)

نسخه‌های قبلی، آی‌پی را وقتی «خوب» می‌دانستند که فقط یک هندشیک WebSocket جواب بدهد، و بعد سرعتش را با دانلود
**مستقیم از `speed.cloudflare.com`** از همان آی‌پی می‌سنجیدند. این فقط سرعت *کامپیوتر شما ↔ سرور لبه‌ی کلودفلر*
را نشان می‌دهد. ترافیک واقعی شما مسیر دیگری دارد:

</div>

<div dir="ltr">

```
V2rayN ──TLS(SNI = دامنه‌ی شما)──▶ آی‌پی کلودفلر ──WebSocket──▶ سرور شما ──▶ اینترنت
```

</div>

<div dir="rtl">

محدودسازی یا مسدودسازی مبتنی بر SNI از طرف ISP، مسیر کلودفلر ← سرور شما، و خراب بودن خود مسیر VLESS در آن
تست دیده نمی‌شدند؛ برای همین یک آی‌پی می‌توانست ۱۰ مگابیت نشان بدهد ولی در V2rayN هیچ‌چیز (حتی speedtest.net)
باز نشود. چند ایراد کوچک‌تر هم باعث گمراهی می‌شد: جواب ساده‌ی `HTTP 200` به‌عنوان WebSocket سالم حساب می‌شد،
کد وضعیت HTTP تست سرعت هرگز بررسی نمی‌شد، و ۸ تست هم‌زمان پهنای باند را بین خودشان تقسیم می‌کردند.

**نسخه‌ی ۴ یک کلاینت VLESS روی WebSocket داخل خودش دارد.** هر آی‌پی با همان SNI / Host / path / UUID
کانفیگ خودتان تست می‌شود:

| مرحله | چه چیزی بررسی می‌شود | هزینه |
|---|---|---|
| ۱. اسکن | TCP + TLS + ارتقای WebSocket باید یک `101` واقعی برگرداند (با `Sec-WebSocket-Accept` درست) | ارزان، هم‌زمانی بالا |
| ۲. تست تونل | یک درخواست HTTPS به `cp.cloudflare.com/generate_204` **از داخل تونل** باید موفق شود — مثل «real delay» در V2rayN | چند رفت‌وبرگشت، فقط برای آی‌پی‌های مرحله‌ی ۱ |
| ۳. دانلود | دانلود از داخل تونل به مدت `--speed-time` ثانیه. آی‌پی‌های کند بعد از حدود ۲٫۵ ثانیه کنار گذاشته می‌شوند | یک آی‌پی در هر لحظه |
| ۴. آپلود | فقط برای آی‌پی‌هایی که مرحله‌ی ۳ را رد کرده‌اند. تکه‌ها از داخل تونل POST می‌شوند و **فقط وقتی حساب می‌شوند که سرور تأییدشان کرده باشد** | یک آی‌پی در هر لحظه |

آی‌پی‌ای که در هر مرحله رد شود هرگز وارد لیست نتایج نمی‌شود؛ پس فقط آی‌پی‌هایی را می‌بینید که ترافیک واقعی عبور می‌دهند.

---

## شروع سریع

۱. Python نسخه‌ی ۳٫۸ یا بالاتر را نصب کنید (`python3 --version` در لینوکس، `python --version` در ویندوز).

۲. بازه‌های آی‌پی را در یک فایل متنی بگذارید — فایل `subnets.example.txt` را به `subnets.txt` کپی کنید.

۳. با لینک `vless://` خودتان اجرا کنید (باید `type=ws` باشد؛ `security=tls` یا `none`).

**لینوکس**

</div>

<div dir="ltr">

```bash
python3 cf_ping.py subnets.txt -c "vless://UUID@your.domain.com:443?type=ws&security=tls&path=%2Fxyz&host=your.domain.com&sni=your.domain.com#name" -t 100 --speed-test --want 10
```

</div>

<div dir="rtl">

**ویندوز** (PowerShell یا cmd — لینک را داخل دابل‌کوتیشن بگذارید)

</div>

<div dir="ltr">

```bat
python cf_ping.py subnets.txt -c "vless://UUID@your.domain.com:443?type=ws&security=tls&path=%2Fxyz&host=your.domain.com&sni=your.domain.com#name" -t 100 --speed-test --want 10
```

</div>

<div dir="rtl">

> اگر داخل فایل `.bat` اجرا می‌کنید به‌جای `%2F` بنویسید `%%2F`. برای رنگ‌ها از Windows Terminal، PowerShell یا
> `cmd` ویندوز ۱۰ به بالا استفاده کنید.

این دستور با ۱۰۰ ترد اسکن می‌کند، به ازای هر ۲۰ آی‌پی تأییدشده تست سرعت می‌گیرد و **به محض اینکه ۱۰ آی‌پی قبول شد
متوقف می‌شود**. فایل `cf_results.json` را باز کنید — بخش `results` از بهترین به بدترین مرتب است و هر مورد یک
`vless_uri` آماده دارد؛ آن را در V2rayN وارد کنید (*Servers ← Import from clipboard*).

یک بار **Ctrl+C** یعنی توقف و ذخیره (پیشرفت و نتایج حفظ می‌شود)؛ بار دوم بلافاصله و بدون ذخیره خارج می‌شود.

### خواندن سرعت‌ها

اسکریپت هم **Mbps** (مگابیت بر ثانیه) و هم کنار آن **MB/s** (مگابایت بر ثانیه، یعنی Mbps ÷ ۸) را چاپ می‌کند —
V2rayN مقدار MB/s را نشان می‌دهد. عبارت `7.25 Mbps (0.91 MB/s)` یک عدد است که دو بار نوشته شده.

## گزینه‌ها

| گزینه | پیش‌فرض | معنی |
|---|---|---|
| `subnets_file` | – | فایل آی‌پی / CIDR، هر خط یک مورد (`#` = توضیح) |
| `-c, --config` | – | لینک `vless://` شما. برای تست تونل و سرعت لازم است |
| `-s, --sni` | – | اسکن فقط-TLS برای یک دامنه (بدون کانفیگ) |
| `-t, --threads` | ۵۰ | تعداد ترد اسکن |
| `-w, --wait` | ۳٫۰ | تایم‌اوت هر مرحله‌ی شبکه (ثانیه) |
| `-p, --port` | از کانفیگ / ۴۴۳ | تغییر پورت |
| `-o, --output` | `cf_results.json` | فایل نتایج |
| `-r, --resume` | `cf_progress.json` | فایل پیشرفت (بخش *ادامه‌ی اسکن*) |
| `--no-verify` | خاموش | فقط `101` وب‌سوکت را چک می‌کند (سریع، اما خیلی از این آی‌پی‌ها ترافیک عبور نمی‌دهند) |
| `--verify-url` | `https://cp.cloudflare.com/generate_204` | آدرسی که برای تأیید هر آی‌پی *از داخل تونل* باز می‌شود (جواب `200` یا `204` انتظار می‌رود) |
| `--down-url` | خودکار | **یک** آدرس دانلود را اجباری می‌کند (`http://` یا `https://`). `{bytes}` حجم درخواستی است که خود اسکریپت انتخاب می‌کند؛ آدرس یک فایل معمولی هم جواب می‌دهد. پیش‌فرض: خودکار، پایین را ببینید |
| `--up-url` | خودکار | **یک** آدرس آپلود را اجباری می‌کند؛ باید بدنه‌ی `POST` را قبول کند |
| `--speed-test` | خاموش | تست واقعی دانلود/آپلود برای آی‌پی‌های تأییدشده (نیاز به `-c`) |
| `--speed-limit` | ۲۰ | با رسیدن به این تعداد آی‌پی تأییدشده، اسکن مکث می‌کند و یک دسته تست سرعت می‌شود |
| `--speed-time` | ۵ | ثانیه برای هر اندازه‌گیری دانلود و آپلود |
| `--min-download` | ۲ | آی‌پی‌های کندتر از این دانلود (Mbps) رد می‌شوند |
| `--min-upload` | ۱ | آی‌پی‌های کندتر از این آپلود (Mbps) رد می‌شوند |
| `--no-upload` | خاموش | تست آپلود انجام نشود |
| `--speed-threads` | ۱ | تعداد تست سرعت هم‌زمان. برای اعداد درست **۱** بگذارید — تست‌های هم‌زمان پهنای باند شما را تقسیم می‌کنند |
| `--want N` | ۰ (خاموش) | به محض قبول شدن N آی‌پی همه‌چیز متوقف شود (بدون `--speed-test`: N آی‌پی تأییدشده) |
| `--sort` | `download` | ترتیب نتایج: `download`، `upload` یا `delay` |
| `--loss-count` | ۰ (خاموش) | تعداد پینگ ICMP برای محاسبه‌ی packet loss (نیاز به `ping`؛ بسیاری از شبکه‌ها ICMP را می‌بندند) |
| `--ping-only`, `--tls13-only` | خاموش | فقط پینگ ICMP / فقط TLS 1.3 (حالت `-s`) |

نکته‌ها:

* **در وقت صرفه‌جویی کنید:** `--want 10` (یا هر عدد دیگر) — معمولاً چند آی‌پی خوب کافی است.
* با بالا بردن `--min-download` / `--min-upload` (مثلاً `--min-download 8`) آی‌پی‌های متوسط را سریع‌تر حذف می‌کنید.
* اینترنت کند یا سرور دور دارید؟ `-w` را بالا ببرید (مثلاً `-w 5`) و `--speed-time` را هم (مثلاً `8`).
* هنگام تست، دانلودهای دیگر را ببندید؛ آن‌ها همان پهنای باندی را می‌خورند که در حال اندازه‌گیری است.

## خروجی

</div>

<div dir="ltr">

```jsonc
{
  "count": 2,
  "speed_tested": 2,
  "results": [                       // verified, best first
    {
      "ip": "104.16.12.34", "tls": "1.3",
      "latency_ms": 55.5,            // TCP + TLS + WebSocket upgrade
      "tunnel_ms": 103.7,            // full request through the tunnel (like V2rayN real delay)
      "download_mbps": 23.4, "upload_mbps": 8.1, "verdict": "pass",
      "vless_uri": "vless://UUID@104.16.12.34:443?type=ws&...#name-104.16.12.34-D23.4-U8.1"
    }
  ],
  "rejected": [                      // too slow / failed the real test
    { "ip": "104.16.99.1", "verdict": "slow", "reason": "download too slow (0.94 Mbps)" }
  ]
}
```

</div>

<div dir="rtl">

آی‌پی‌هایی که پیدا شده‌اند ولی هنوز تست سرعت نشده‌اند (مثلاً بعد از Ctrl+C) بدون `verdict` در `results` می‌مانند و
دفعه‌ی بعد که اسکن را ادامه دهید خودکار تست می‌شوند.

### ادامه‌ی اسکن

فایل `cf_progress.json` آی‌پی‌های اسکن‌شده را نگه می‌دارد و `cf_results.json` نتایج را. همان دستور را دوباره اجرا
کنید تا ادامه پیدا کند. این دو فایل مال **یک کانفیگ + یک حالت** هستند: اگر کانفیگ (UUID، host، path، SNI، پورت،
`--no-verify`، `--verify-url`) عوض شود، پیشرفت قبلی نادیده گرفته می‌شود و اسکن از اول شروع می‌شود. برای نگه داشتن
چند اسکن کنار هم از `-o` و `-r` استفاده کنید.

## عیب‌یابی

| نشانه | علت محتمل |
|---|---|
| همه‌ی آی‌پی‌ها: `HTTP 400/404 (wrong path/config?)` | `path`، `host` یا `sni` در لینک اشتباه است |
| برای همه `WS ok, tunnel dead: …` | UUID اشتباه است، سرور شما خاموش است، یا سرور شما به هاستِ `--verify-url` دسترسی ندارد. با `--no-verify` می‌بینید لبه اصلاً جواب می‌دهد یا نه (این آی‌پی‌ها *اثبات نشده‌اند* که کار کنند) |
| `No download test server answers your server` | همه‌ی سرورهای تست سرعت یا درخواست سرور شما را رد کردند یا در دسترس نبودند. متنِ جلوی هر هاست همان جوابِ آن است. به `--down-url` یک فایل بزرگ بدهید که سرور شما بتواند دانلود کند. آی‌پی‌ها **تست‌نشده** می‌مانند |
| `fake WS 101` | چیزی در مسیر شبکه جواب‌های WebSocket جعلی می‌دهد |
| سرعت‌ها هنوز از V2rayN بیشتر است | V2rayN آدرس و مدت دیگری را می‌سنجد؛ ترافیک دیگر روی خط؛ `--speed-time 10` را امتحان کنید. آی‌پی‌ها را با هم مقایسه کنید، نه عدد مطلق را |
| `ping` پیدا نشد | ایمیج‌های حداقلی لینوکس: `sudo apt install iputils-ping` (فقط برای `--ping-only` / `--loss-count` لازم است) |

### تست سرعت با کدام سرور انجام می‌شود؟

ترافیک تست سرعت **از سرور شما** (همان که پشت تونل است) به یک سرور تست می‌رود؛ پس مهم این است که *سرور شما* به چه
چیزی دسترسی دارد. سرور `speed.cloudflare.com` گاهی چنین درخواست‌هایی را رد می‌کند (`HTTP 403` یا یک صفحه‌ی HTML با
کد `404` برای آی‌پی‌های دیتاسنتر). برای همین اسکریپت قبل از اولین دسته، این سرورها را **یک بار در هر اجرا و از داخل
تونل شما** امتحان می‌کند و اولین سروری را که جواب بدهد برمی‌دارد — برای همه‌ی آی‌پی‌ها همان یک سرور، تا عددها قابل
مقایسه بمانند:

</div>

<div dir="ltr">

| | Download | Upload |
|---|---|---|
| 1 | `speed.cloudflare.com/__down` | `speed.cloudflare.com/__up` |
| 2 | `speed.hetzner.de/100MB.bin` | `speedtest.tele2.net/upload.php` |
| 3 | `cachefly.cachefly.net/100mb.test` | |
| 4 | `speedtest.tele2.net/100MB.zip` | |
| 5 | `proof.ovh.net/files/100Mb.dat` | |

</div>

<div dir="rtl">

سرورهای ردشده و دلیلشان (کد وضعیت، هدر `server:` و عنوان صفحه) چاپ می‌شود، مثلاً
`skipped speed.cloudflare.com: HTTP 404 [server: cloudflare] "404 Not Found"`. اگر هیچ سرور آپلودی جواب ندهد اسکریپت
**بدون** تست آپلود ادامه می‌دهد و همین را اعلام می‌کند. فایل‌های تست عمومی ممکن است جابه‌جا شوند یا از بین بروند؛ برای
استفاده از فایل خودتان (فایل بزرگی روی سرور یا CDN خودتان بهترین است):

</div>

<div dir="ltr">

```bash
python3 cf_ping.py subnets.txt -c "vless://..." --speed-test --down-url "https://your-server.invalid/100mb.bin" --no-upload
```

</div>

<div dir="rtl">

`--down-url` / `--up-url` فقط **یک** آدرس را اجباری می‌کنند — بدون جایگزین. `--up-url` باید سروری باشد که بدنه‌ی
`POST` را قبول می‌کند.
عبارت `your-server.invalid` در مثال بالا فقط **جای‌نگهدار** است — آن را با آدرس یک فایل واقعی عوض کنید (اسکریپت
هاست‌های جای‌نگهدار مثل `example.com` را قبول نمی‌کند).

## محدودیت‌ها

* فقط **VLESS روی WebSocket** تست می‌شود (`type=ws` و `security=tls` یا `none`). gRPC، Reality، VMess و Trojan پشتیبانی نمی‌شوند.
* ClientHello مربوط به TLS از خود Python می‌آید نه uTLS — مقدار `fp=` لینک شما هنگام اسکن نادیده گرفته می‌شود.
  اگر ISP شما با اثر انگشت TLS رفتار متفاوتی دارد، نتیجه ممکن است با کلاینت واقعی فرق کند.
* گواهی‌ها بررسی نمی‌شوند (این یک اسکنر است). بلوک‌های IPv6 نمونه‌گیری می‌شوند (۴۰۹۶ آدرس)، بازه‌های IPv4 کامل پیمایش می‌شوند.
